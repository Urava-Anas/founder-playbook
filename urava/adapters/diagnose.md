# Urava Adapter — Diagnose

Wraps upstream `diagnose/SKILL.md` for Developer House routing.

## Use when

The founder problem is broad, multiple commercial symptoms overlap, or the correct framework is unclear.

## Urava constraints

1. Diagnose must identify the **current bottleneck**, not the most interesting problem.
2. Before routing, check whether the real blocker is technical delivery, security, production readiness, legal/financial authority, or execution capacity. If yes, route to Developer House rather than forcing a business framework.
3. Output one primary intelligence module, one optional secondary module, and one concrete next action.
4. Do not recommend broad strategy work while an existing verified completion gate is the binding constraint.
5. Recommendations requiring spend, pricing commitments, production/external effects, or ownership changes remain founder-gated.

## Output packet

- Symptom
- Best-supported root cause
- Evidence used
- Primary module
- Optional secondary module
- One action
- Success/failure evidence to collect
- Stop/re-evaluate condition

## Example

If Orbit has a broken production acceptance path, do **not** route to StoryBrand because the website can be improved. The binding constraint is product/release execution, so route to Developer House Release/QA/Deployment skills.
